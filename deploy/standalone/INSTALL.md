# Портал «Одной Крови». Инструкция по установке и эксплуатации standalone-экземпляра

## 1. Назначение

Настоящий пакет представляет собой экземпляр программного обеспечения
«Портал Одной Крови» (далее — Портал) для развертывания в тестовой среде
эксперта с целью проверки функциональных характеристик.

Портал — веб-приложение для поиска доноров крови среди животных:
соединяет владельцев питомцев, которым нужна донорская кровь
(реципиентов), и владельцев здоровых питомцев, готовых стать донорами.

Пакет полностью автономен: включает все необходимые docker-образы
(в том числе СУБД PostgreSQL и Redis) и не требует доступа в интернет.

## 2. Требования к среде

| Требование | Значение |
|---|---|
| ОС | Linux / macOS / Windows с WSL2 |
| Docker Engine | 24.0 или новее |
| Docker Compose | v2 (плагин `docker compose`) |
| Свободное место на диске | ~3 ГБ |
| Свободные порты | 80 (TCP) — веб-интерфейс Портала |

## 4. Установка

### 4.1. Загрузка docker-образов

Из корня распакованного пакета выполните:

```bash
docker load -i images/backend-standalone.tar
docker load -i images/frontend-standalone.tar
docker load -i images/infra-standalone.tar
```

### 4.2. Запуск

```bash
docker compose -f docker-compose.standalone.yml up -d
```

Порядок запуска автоматизирован:
1. стартуют PostgreSQL и Redis;
2. стартует backend, при первом запуске применяет миграции схемы БД;
3. одноразовый контейнер `seed` применяет справочники и демо-данные
   (после успешного healthcheck backend);
4. стартует веб-сервер frontend.

Полная готовность наступает через ~1–2 минуты (контейнер `seed` завершается).

### 4.3. Проверка установки

- Портал: откройте в браузере **http://localhost**
- Здоровье API: `http://localhost/health` — ответ `OK`
- Статус контейнеров: `docker compose -f docker-compose.standalone.yml ps`
  (все сервисы, кроме `seed`, в состоянии Up, `seed` — Exited (0))

демонстрационного пользователя (в standalone-экземпляре не используется
аутентификация через мессенджеры Telegram/Messenger Max, которая

## 6. Описание процессов и микроконтейнеров

| Контейнер | Образ | Процесс | Назначение |
|---|---|---|---|
| backend | odnoi-krovi-app/backend:standalone | `/root/main` (Go, порт 3000) | Монолитный backend: HTTP API (Huma v2), доменная логика (DDD+CQRS), доступ к БД через ORM Ent, планировщик фоновых задач |
| frontend | odnoi-krovi-app/frontend:standalone | Caddy (порт 80) | Раздача SPA (React), проксирование `/api/*` на backend |
| postgres | postgres:16-alpine | PostgreSQL 16 (порт 5432) | Хранение данных Портала |
| redis | redis:7-alpine | Redis 7 (порт 6379) | OTP-коды, кеш уведомлений, pub/sub событий |
| seed | postgres:16-alpine | psql (одноразовый) | Применение справочников и демо-данных при первом старте |

Расположение файлов ПО внутри контейнера backend:
- `/root/main` — исполняемый файл backend;
- `/root/docs` — спецификация OpenAPI;
- `/root/migrations` — SQL-миграции.

Данные хранятся в docker-томах: `pgdata` (база данных), `media` (фото
питомцев; в standalone-режиме файловое хранилище работает на локальном
диске, в промышленной эксплуатации — S3-совместимое облако).

## 7. Проверка функциональных характеристик

Основные сценарии, доступные после установки:

1. **Профиль донора** — карточки питомцев с фото, группой крови,
   породой, статусом допуска к донации.
2. **Список заявок на кровь** (раздел поиска доноров) — активные заявки
   реципиентов с автоматическим подбором подходящих доноров.
3. **Карточка заявки** — объем и компоненты крови, регион, описание.
4. **Справочники** — 89 регионов РФ, 316 пород, группы крови,
   компоненты крови.
5. **Регистрация питомца** — создание карточки донора через интерфейс.
6. **Загрузка фото** — файлы сохраняются через API и раздаются
   веб-сервером.
7. **Статистика портала** — сводная информация о пользователях и донациях.

## 8. Ограничения standalone-экземпляра

Компоненты, требующие внешних сервисов, в standalone-экземпляре
отключены (в промышленной эксплуатации задействованы):

- уведомления через Telegram Bot API и Messenger Max (боты — точки входа
  в Портал, не входят в проверяемый веб-экземпляр);
- подтверждение номера телефона голосовым OTP-кодом (внешний сервис
  Twin24);
- выгрузка алертов об ошибках во внешний webhook.

## 9. Остановка и удаление

```bash
# Остановка (данные сохраняются):
docker compose -f docker-compose.standalone.yml stop

# Повторный запуск:
docker compose -f docker-compose.standalone.yml start

# Полное удаление, включая данные:
docker compose -f docker-compose.standalone.yml down -v
```

## 10. Диагностика

| Симптом | Действие |
|---|---|
| Порт 80 занят | Измените порт в `docker-compose.standalone.yml` (сервис `frontend`, секция `ports`, например `"8080:80"`), откройте http://localhost:8080 |
| Портал не открывается | `docker compose -f docker-compose.standalone.yml ps`; дождитесь статуса healthy у backend |
| Ошибки при запуске | Логи: `docker compose -f docker-compose.standalone.yml logs backend` |
| Демо-данные не применились | `docker compose -f docker-compose.standalone.yml logs seed`; повторный запуск: `docker compose -f docker-compose.standalone.yml up seed` |
| Полный сброс | `docker compose -f docker-compose.standalone.yml down -v && docker compose -f docker-compose.standalone.yml up -d` |
