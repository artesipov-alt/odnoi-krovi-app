# Журнал изменений

Все значительные изменения в этом проекте будут документированы в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
и проект следует [Семантическому Версионированию](https://semver.org/lang/ru/).

## [3.4.4] - 2026-03-13

### Добавлено
- **Поля статуса поиска крови в модели питомца:** Добавлены новые поля `SearchingBlood` (булево) и `HaveBloodReqApplication` (булево) в модель `Pet` для отслеживания статуса поиска крови.
- **Новое значение `RECIPIENT_LIST` в перечислении онбординга:** Добавлено новое значение `RECIPIENT_LIST` в перечисление `OnBoarding` для расширения возможностей онбординга.

### Изменено
- **Обновлена версия API до 3.4.4:** Версия API обновлена до 3.4.4.
- **Обновлена схема Ent и сгенерированные файлы:** Схема Ent была обновлена для включения новых полей `searching_blood` и `have_blood_req_application` в сущность `Pet`, а также для добавления нового значения в перечисление `OnBoarding`. Соответствующие сгенерированные файлы Ent были обновлены.
- **Расширены DTO и обработчики для поддержки новых полей и значения:** DTO `Pet` и связанные обработчики были обновлены для корректной обработки и использования новых полей и значения перечисления.

### Технические детали
- В `ent/schema/pet.go` добавлены поля `field.Bool("searching_blood").Default(false)` и `field.Bool("have_blood_req_application").Default(false)`.
- В `ent/schema/bloodsearchrequest.go` (или соответствующем файле, где определено перечисление `OnBoarding`) добавлено значение `RECIPIENT_LIST` в перечисление.
- Выполнен `go generate ./ent` для обновления сгенерированных файлов Ent.
- В `dto/pet.go` добавлены поля `SearchingBlood bool `json:"searchingBlood"` и `HaveBloodReqApplication bool `json:"haveBloodReqApplication"`.
- В `dto/blood_search.go` обновлено перечисление `OnBoarding` для включения `RECIPIENT_LIST`.
- В `internal/handlers/pet/query/get_by_id_handler.go` и `internal/handlers/pet/query/get_by_user_handler.go` обновлена логика для включения новых полей в ответы.
- В конфигурации Huma API обновлена версия до 3.4.4.

## [3.3.0] - 2026-03-05

### Добавлено
- **Новая сущность UserIdentity:** Введена сущность `UserIdentity` для поддержки аутентификации через внешние провайдеры, включая поля для провайдера, ID пользователя провайдера и метаданные. Установлена связь O2M с сущностью `User`.
- **Эндпоинты аутентификации пользователей:** Добавлены новые эндпоинты для аутентификации пользователей, включая модели `AuthUserBody` и `AuthUserResult`. Введены поля `ProviderID` и `ProviderName` в модель `User`, заменяющие `TelegramID`, для поддержки различных мессенджеров.
- **Отслеживание UTM-истории:** Добавлена сущность `UtmHistory` для отслеживания UTM-параметров (source, medium, campaign, content, term) при регистрации пользователей. В модель `User` добавлено поле `OriginSource` для хранения источника привлечения.
- **Поддержка транзакций в операциях с пользователями:** Операции создания и обновления пользователей теперь используют транзакции для обеспечения атомарности, включая обработку конфликтов по телефону с объединением аккаунтов.
- **Сервис max-bot:** Добавлен новый сервис `max-bot` в docker-compose и workflow развертывания, с рефакторингом команд и middleware для улучшения организации и обработки ошибок.
- **Функциональность переноса UTM-истории:** Реализован метод `TransferUTMHistory` для перемещения UTM-данных между пользователями и метод `DeleteUTMHistoryByUserID` для очистки.

### Изменено
- **Рефакторинг обработки UTM и метаданных:** Поле `MetaData` в модели `User` изменено с `map[string]any` на `map[string]string`, добавлена структурированная модель `Metadata`. UTM-данные теперь извлекаются и сохраняются в базе данных. Индекс UTM-истории упрощен для использования `user_id` и `utm_campaign`.
- **Обновление схемы пользователя:** Поле `TelegramID` помечено как опциональное и устаревшее. Поле `phone` теперь уникально. Добавлена связь с `UserIdentity`. Комментарии схемы переведены на русский язык.
- **Переименование пакетов и директорий:** Пакет `odnoi-krovi-bot` переименован в `odnoi-krovi-max-bot` и `odnoi-krovi-tg-bot`. Директория `bot` переименована в `tg-bot`, с добавлением новой директории `max-bot`.
- **Рефакторинг хендлеров и сервисов:** Хендлеры команд бота реорганизованы для лучшей обработки ошибок. Удален код регистрации пользователя из команд. Добавлена поддержка upsert в схему Ent. Метод `NewDonorPreference` переименован в `DefaultDonorPreference`.
- **Обновление обработки ошибок:** Ошибки Grammy и Bot заменены на `MaxError` в обработчике ошибок.
- **Обновление workflow и Taskfile:** Задача `dev-bot` переименована в `dev-tg-bot`, добавлена `dev-max-bot`. Переменная окружения изменена с `PROD_BOT_API_KEY` на `TG_BOT_TOKEN`.

### Удалено
- **Параметр предпочтений донора из NewUser:** Удален параметр `donorPreference` из функции `NewUser`, добавлен метод `DeleteDonorPreferenceByUserID` в репозиторий.
- **Поле MetaData из модели User:** Поле `MetaData` удалено из модели `User`, логика обработки UTM переработана.

### Технические детали
- В `ent/schema/user.go` добавлены поля `ProviderID`, `ProviderName`, `OriginSource`, связь с `UserIdentity` и `UtmHistory`. Поле `phone` сделано уникальным.
- В `ent/schema/user_identity.go` определена новая схема с полями для провайдера и метаданных.
- В `ent/schema/utm_history.go` добавлена схема с полями UTM-параметров и индексом.
- В `internal/handlers/user_handler.go` добавлен `AuthHandler` и обновлены методы для поддержки транзакций и провайдеров.
- В `internal/repositories/user_repository.go` добавлены методы для работы с UTM-историей, идентичностями и транзакциями.
- В `dto/user.go` обновлены структуры для новых полей, `TelegramID` помечен как опциональный.
- В `cmd/max-bot/` и `cmd/tg-bot/` реорганизованы хендлеры и middleware.
- Обновлены `docker-compose.yml`, `deploy.yml` и `Taskfile.yaml` для поддержки `max-bot`.

- **Ent Framework:** Полный переход на Ent в качестве ORM, предоставляющий мощные возможности для работы с базой данных, включая:
