# Журнал изменений

Все значительные изменения в этом проекте будут документированы в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
и проект следует [Семантическому Версионированию](https://semver.org/lang/ru/).


## [2.1.1] - 2026-01-27

### Изменено
- **Исправлена опечатка в предзагрузке репозитория питомцев:** Изменено "Analysis" на "Analyses" для корректной предзагрузки связанных анализов.
- **Реорганизованы методы сервиса:** Методы `buildFullPhotoURLs` перемещены после `ConfirmPhotos` в соответствующих сервисах для улучшения логической последовательности.
- **Метод `calculateAgeFields` стал методом `PetService`:** Метод `calculateAgeFields` теперь является частью `PetService` и вызывается при создании питомца для автоматического расчета возраста.

### Технические детали
- В `pet_repository.go` изменено имя связи для предзагрузки с `Analysis` на `Analyses`.
- В `s3_service.go` и других сервисах, использующих S3, методы `buildFullPhotoURLs` перемещены после `ConfirmPhotos`.
- Метод `calculateAgeFields` интегрирован в `pet_service.go` как приватный метод `(s *PetService) calculateAgeFields(...)` и вызывается в методе `CreatePet`.


## [2.1.0] - 2026-01-20

### Добавлено
- **Поддержка S3 для заявок на кровь (Blood Requests):** Теперь S3 хранилище поддерживает загрузку и подтверждение фотографий для сущности `Blood Request`.
- **Массив `photo_urls`:** В схемы `User`, `Pet` и `BloodRequest` добавлено новое поле `photo_urls` (массив строк) для хранения ссылок на фотографии.
- **Год в путях S3:** В пути объектов S3 для `User`, `Pet` и `BloodRequest` добавлен текущий год для лучшей организации хранения.

### Изменено
- **Переработана логика S3 хранилища:**
    - S3 теперь принимает количество фотографий и тип сущности (`User`, `Pet`, `BloodRequest`).
    - Возвращает соответствующее количество предзаполненных ссылок для загрузки фотографий.
    - Подтверждение загрузки фотографии также переработано и принимает ID сущности и путь подтверждения.
- **Обновлены схемы Ent:** Схемы `User`, `Pet` и `BloodRequest` обновлены для включения поля `photo_urls`.
- **Поддержка `Blood Request ID`:** Добавлена поддержка `Blood Request ID` как для предзаполненных URL, так и для URL аватаров.

### Технические детали
- В `schema/user.go`, `schema/pet.go` и `schema/bloodrequest.go` добавлено поле `photo_urls` типа `[]string`.
- Логика генерации предзаполненных URL и подтверждения загрузки в S3 сервисе обновлена для учета типа сущности и добавления года в путь.
- Обновлены соответствующие DTO и обработчики для работы с новым полем `photo_urls` и измененной логикой S3.

## [2.0.1] - 2026-01-12 - Фундаментальный Рефакторинг и Переход на Современный Стек (Супер-Релиз)

Этот релиз представляет собой **полную переработку и фундаментальный рефакторинг** всего бэкенда, закладывающий прочную основу для будущих проектов и обеспечивающий высокую производительность, надежность и удобство разработки. Проект теперь служит образцом для создания современных Go-бэкендов, готовых к масштабированию и легкой поддержке.

### Добавлено
- **Huma v2 (OpenAPI 3.1):** Полный переход на Huma для построения API, обеспечивающий автоматическую генерацию высококачественной документации OpenAPI 3.1, строгую валидацию запросов/ответов и улучшенную структуру API.
- **Стандартный `net/http`:** Использование нативного `net/http` mux для маршрутизации, что обеспечивает максимальную гибкость и производительность без зависимостей от тяжеловесных фреймворков.
- **Ent Framework:** Полный переход на Ent в качестве ORM, предоставляющий мощные возможности для работы с базой данных, включая:
    - **Схемы данных:** Все GORM модели переписаны на декларативные Ent схемы.
    - **Интерцепторы:** Внедрение кастомных интерцепторов Ent для расширения функциональности ORM (например, для автоматического управления полями `CreatedAt`/`UpdatedAt`).
    - **Миксины:** Использование миксинов Ent для реализации общих паттернов, таких как `Soft Delete`, что значительно упрощает управление жизненным циклом сущностей.
- **Единая система обработки ошибок (`apperrors`):** Разработан и интегрирован централизованный пакет `apperrors` для унификации всех ошибок приложения, обеспечивающий консистентные ответы API и легкую диагностику.
- **`Request ID` для отслеживания:** Внедрение middleware для автоматического добавления уникального `Request ID` к каждому запросу, что значительно упрощает отслеживание запросов через логи и мониторинг.
- **Интеграция `charmbracelet/log` поверх стандартного `slog`:** Переход от тяжеловесных логгеров (например, Zap) к стандартному `slog` с красивой и функциональной оберткой `charmbracelet/log`, что обеспечивает улучшенное структурированное логирование с поддержкой различных форматов (текст, JSON) и уровней детализации при минимальных зависимостях.

### Изменено
- **Архитектурный Рефакторинг:** Полная переработка архитектуры бэкенда с переходом от Echo к Huma и от GORM к Ent, а также **отказ от избыточных внешних зависимостей в пользу стандартных библиотек Go**, что привело к значительному улучшению модульности, чистоты кода и производительности.
- **Переписанные Хендлеры:** Все HTTP-обработчики были полностью переписаны с учетом новой архитектуры Huma и `net/http`, обеспечивая более чистый и эффективный код.
- **Обновленная Структура DTO:** Структуры Data Transfer Objects (DTO) были переработаны для лучшей ясности, консистентности и соответствия новым схемам Ent.
- **Улучшенное Логирование:** Оптимизировано логирование во всех слоях приложения, включая middleware, сервисы и обработчики, для предоставления более полной и полезной информации.
- **Рефакторинг `Soft Delete`:** Реализация мягкого удаления теперь полностью основана на миксинах и интерцепторах Ent, обеспечивая надежное и легко расширяемое решение.
- **Удаление Устаревших Компонентов:** Полностью удалены все зависимости и код, связанные с Echo, GORM и старой документацией Swagger.

### Удалено
- Фреймворк Echo и все связанные с ним зависимости.
- ORM GORM и все связанные с ним зависимости.
- Старая документация Swagger и связанные генераторы.
- Микросервис `blood-microservice` (его функционал был интегрирован в основной бэкенд для упрощения архитектуры монорепозитория).
- **Тяжеловесные логгеры (например, Zap) и другие избыточные внешние библиотеки**, замененные на стандартные решения Go.

### Технические детали
- **Обновленные Зависимости Go:** Все зависимости проекта были обновлены до последних стабильных версий.
- **Оптимизация Зависимостей:** Принято стратегическое решение о **минимизации внешних зависимостей и максимальном использовании стандартных библиотек Go**, что повышает стабильность, безопасность и упрощает поддержку проекта.
- **Реорганизация `internal/`:** Проведена значительная реорганизация структуры каталога `internal/` для повышения модульности, четкого разделения ответственности и улучшения навигации по коду.
- **Улучшенная Валидация:** Внедрены более строгие механизмы валидации данных на уровне API и ORM.
- **Подготовка к Будущему:** Текущая архитектура обеспечивает высокую гибкость и готовность к дальнейшему развитию, позволяя легко добавлять новые функции и сервисы.
